## 4. Treatment rules (frozen before code)

1. **Object creation** (`new T(…)`, target-typed `new(…)`) with a relevant
   argument gets a `calls[]` record:
   - `callee` is the constructor's `functions[]` key (`T..ctor`, exactly how
     constructor records are already named), with `sig` and `first_party`
     computed as for invocations;
   - arguments bind by declared ordinal under the same rules (named
     resolved, `params`/`ref`/`out` opaque);
   - `site` is the creation expression's start;
   - `form` follows its parent: `using var w = new …` → `initializer`, a
     bare `new …;` → `statement`, anything else → `expression`.
2. **Constructor initializer** (`: base(…)` / `: this(…)`) with a relevant
   argument gets a `calls[]` record:
   - `callee` is the target constructor's key;
   - `site` is the initializer's start, and `statement_line` is its line;
   - `form` is `statement`: it executes as a statement and its result is
     discarded.
3. **Value-preserving unwrap before classification.** `ArgFact` strips:
   - parentheses (as today);
   - the null-forgiving `!`, which has no runtime effect;
   - a cast whose conversion is identity or a non-user-defined reference
     conversion, because it is the same object.

   The unwrapped operand is then classified as usual, so `(Stream)p` →
   `param`, and `(Stream)fs` → `var`. A cast that is boxing, unboxing,
   user-defined, or anything else → `opaque`, with the handle bit of its
   operand kept.
4. **Opaque but relevant.** For `x as T`, `c ? a : b` and `a ?? b` the slot
   is `opaque`. The handle bit is true iff one of the value operands (`x`;
   `a`/`b`) is itself a handle after unwrapping. No other expression form
   changes.
5. **No vocabulary change.** No new `kind`, `form`, field, or enum value, and
   the schema is untouched. `spec/OwnIR.md` §5.2's prose names the call forms
   covered and the unwrap rule. `sourceSite` stays UNBOUND: the doors still
   do not read the sidecar.
6. **Everything outside `guarded_facts` stays byte-identical**: `body`,
   `params`, `sig`, record order and presence. `ConsumesParam`,
   `LowerFlowBody` and the emission gates are untouched.
