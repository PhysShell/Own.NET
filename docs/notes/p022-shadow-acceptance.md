## §1 — The inventory: where the format, the scope and the versions are pinned

Taken **before** anything moved, on both sides, by constant *and* by the test
that fails when the constant does. The point of taking it first is that a
version bump touches more places than a grep for the constant finds: a manifest
carries the number as data, a golden carries it as bytes, and a test asserts a
*consequence* of it without naming it at all.

### 1.1 The artifact format version — `REPRO_VERSION`

| where | kind | what it holds |
|---|---|---|
| `ownlang/repro.py::REPRO_VERSION` | constant (reference) | the emitter's version; stamped into every artifact by `project_repro` |
| `ownlang/repro.py::verify_repro` | gate | refuses an artifact whose `repro_version` is not this one |
| `rust/crates/own-shadow/src/artifact.rs::REPRO_VERSION` | constant (port) | the port's independent copy; `verify` refuses a mismatch |
| `tests/fixtures/repro/manifest.json` → `repro_version` | **data** | the ledger's own copy, checked against the emitter by `_manifest()` |
| `tests/fixtures/repro/digests.json` → `repro_version` | **data** | the digest ledger's copy, regenerated by `_render_digests` |
| `tests/fixtures/repro/*.repro.json` | **bytes** | every committed artifact carries the number in its first line |
| `tests/test_repro_fixtures.py::_structural_controls` | control | `expect("a wrong format version", …)` forges `REPRO_VERSION + 1` and requires a refusal |
| `own-shadow/tests/repro.rs::verify_refuses_each_structural_violation` | control | the port's twin of the same forgery |
| `own-shadow/tests/repro.rs::every_committed_artifact_round_trips_and_verifies` | replay | reads the number out of each golden and asserts it |

### 1.2 The trace surface version — `TRACE_VERSION`

| where | kind |
|---|---|
| `ownlang/repro.py::TRACE_VERSION` | constant (reference) |
| `rust/crates/own-shadow/src/trace.rs::TRACE_VERSION` | constant (port) |

### 1.3 The reduction version and its scope — `REDUCTION_VERSION`, `REDUCTION_SCOPE`

| where | kind | what it holds *before* this work |
|---|---|---|
| `ownlang/repro.py::REDUCTION_VERSION` | constant (reference) | `1` |
| `ownlang/repro.py::REDUCTION_SCOPE` | constant (reference) | `("lowered", "summaries")` — a **third copy** of a layer list |
| `rust/crates/own-shadow/src/reduce.rs::REDUCTION_VERSION` | constant (port) | `1` |
| `rust/crates/own-shadow/src/reduce.rs::REDUCTION_SCOPE` | constant (port) | `["lowered", "summaries"]` |
| `tests/fixtures/repro/*.reduction.json` → `scope`, `out_of_scope` | bytes | the scope as data, plus the refusal reason per excluded layer |
| **`own-shadow/tests/reduce.rs::the_verdict_layer_is_refused_not_silently_skipped`** | **the pin** | asserts `!REDUCTION_SCOPE.contains("verdicts")` **and** that every committed reduction records the refusal |
| **`tests/test_repro_fixtures.py::_reduction_controls`** (the Python twin) | **the pin** | `if "verdicts" in REDUCTION_SCOPE: fail`, plus the same `out_of_scope` assertion |

The two pins are the tests D-4 flips. They are named here because they are the
only two places in the tree that say the verdict layer is *deliberately* out of
scope rather than merely absent — and a scope widened without flipping them
would be a scope widened with its own alarm still armed.

### 1.4 The layer vocabulary — `LAYER_ORDER`

| where | kind |
|---|---|
| `ownlang/repro.py::LAYER_ORDER` | constant (reference) |
| `ownlang/repro.py::LAYER_ORDER_SEMANTICS` | the per-layer ordering declaration, keyed by the same names |
| `ownlang/repro.py::_LAYER_STEPS` | the trace projection, keyed by the same names; `trace_layer` raises for a layer with no projection |
| `rust/crates/own-shadow/src/artifact.rs::LAYER_ORDER` | constant (port) |
| `rust/crates/own-shadow/src/trace.rs::order_semantics` | the port's twin of the semantics table |
| `verify_repro::_verify_layers` / `artifact.rs::verify_layers` | gate: every engine reports **exactly** these layers, in this order |
| `own-shadow/tests/engine.rs::both_engines_report_the_same_layers_in_the_same_order` | structural replay |
| `own-shadow/tests/trace.rs::the_declared_order_semantics_are_the_frozen_ones` | control |

D-4's rule — `REDUCTION_SCOPE` is `LAYER_ORDER`, never a third copy — is
recorded against this row: before the change the tree held the layer list three
times (order, semantics, scope) and the third could drift silently, because
nothing compared it to the first.

### 1.5 The engine-entry authorship rule — `_foreign_engines`

| where | kind |
|---|---|
| `tests/test_repro_fixtures.py::_foreign_engines` | the reference's carry-through: reads back the committed artifact and keeps every entry whose `id` is not its own |
| `tests/test_repro_fixtures.py::write()` | the only caller; the reference never authors `rust-own-bridge` |
| `own-shadow/tests/engine.rs::with_our_entry` | the port's mirror: replaces only `rust-own-bridge`, keeps the frozen engine order |
| `own-shadow/tests/engine.rs::this_engine_reproduces_its_committed_capture` | the gate: a missing or stale `rust-own-bridge` entry is a divergence, never a regeneration |

This is the surface B-3 tightens. `_foreign_engines` carries; it never authors —
and under v3 it must additionally **refuse to carry** an entry that does not
attest what it consumed, because a v2 entry promoted into a v3 artifact would
be a `consumed` claim no execution ever made.

### 1.6 The verification chains

| side | entry point | what it recomputes today |
|---|---|---|
| reference | `ownlang/repro.py::verify_repro` | the format version and member set; the input envelope; **the canonical hash, recomputed from the embedded document**; the engine array against the frozen vocabulary and order; each engine's layer array against `LAYER_ORDER`; each layer envelope's status/payload agreement; each projection |
| port | `rust/crates/own-shadow/src/artifact.rs::verify` | the same rules, as an independent reading — a divergence between the two verifiers is itself a finding |

Both are *structural + canonical*. Neither can currently answer B-1's question
at all, because no artifact carries the bytes: the chain starts at
`input.document`, which is already parsed.

## §2 — What was measured, and what will move

### 2.1 The byte-variant measurement (both readers, every variant)

Taken by `tests/test_byte_variants.py` (the reference's column) and
`rust/crates/own-shadow/tests/byte_variants.rs` (the port's), over the
committed byte corpus in `tests/fixtures/repro/variants/`. Each engine writes
only its own column, exactly as the reproduction artifact's two halves do; the
ledger is `tests/fixtures/repro/variants/byte_variants.json`.

Every variant is a rewriting of one committed document,
`tests/fixtures/repro/canonical_minimal.facts.json`.

| variant | transform | reference | port | class |
|---|---|---|---|---|
| `plain` | the committed bytes | accepted | accepted | raw variant |
| `crlf` | every LF → CRLF | accepted | accepted | raw variant |
| `no_trailing_newline` | trailing newline removed | accepted | accepted | raw variant |
| `extra_trailing_newline` | one more trailing newline | accepted | accepted | raw variant |
| `whitespace_expanded` | re-serialized, four-space indent | accepted | accepted | raw variant |
| `whitespace_compact` | re-serialized, no insignificant whitespace | accepted | accepted | raw variant |
| `key_order_reversed` | top-level members written in reverse | accepted | accepted | raw variant |
| `bom` | a UTF-8 BOM prepended | **refused** at *parse* — `json.JSONDecodeError: Unexpected UTF-8 BOM (decode using utf-8-sig)` | **refused** — `serde_json`: `expected value at line 1 column 1` | invalid |
| `invalid_utf8` | a lone `0x80` inside a string | **refused** at *decode* — `UnicodeDecodeError: 'utf-8' codec can't decode byte 0x80 …` | **refused** — `serde_json`: `invalid unicode code point` | invalid |
| `malformed_json` | the final byte removed | **refused** at *parse* — `json.JSONDecodeError: Expecting ',' delimiter` | **refused** — `serde_json`: `EOF while parsing an object` | invalid |

**The split, decided from the measurement and not from the brief.** The BOM
lands in the **invalid** class: both readers refuse it, for different stated
reasons, which is exactly the pattern the domain-refusal ledger already
records for `NaN`. Every accepted variant carries **one** canonical identity
and a **distinct** raw digest — which is B-1's sentence made executable, and
is what the attestation has to be able to tell apart.

**Nothing disagreed.** Had any variant been accepted by one reader and refused
by the other, that would be a domain decision for the owner (the shape D-2
records for `-0`) and this work would have stopped and reported it instead of
filing it. That is not prose: `class` is *derived* from the two `accepted`
flags on both sides, so a disagreement is unrepresentable in a green tree —
`tests/test_byte_variants.py::classify` returns `None` and both harnesses fail
naming the decision.

Two asymmetries are recorded rather than smoothed:

* The reference has **two** refusal stages (`decode`, then `parse`) where the
  port has one, because `serde_json` reads bytes and the reference reaches JSON
  through `str`. `invalid_utf8` fires the first; `bom` and `malformed_json` fire
  the second. The ledger records the stage per side.
* The port's **typed door** (`serde_json::from_slice::<own_ir::OwnIr>`) is a
  different gate from its value reader and is recorded separately
  (`typed_door_accepted`). A document the value reader names and the door
  refuses is a *layer* refusal with a declared boundary (#294 OD-1), never an
  unnameable input — conflating the two is how a declared boundary would come
  to read as a parse failure.

### 2.2 The churn budget

**Nothing else under `tests/fixtures/`.**

### 2.3 The second OD-1 control, and why the corpus needs it

The typed door refuses a document **upstream of every layer**, so one refusal
produces three refused layer records — which is why the frozen boundary policy
D-5 defines has three entries, one per layer. The shadow corpus carries
**one** document that reaches it today (`verdict_door_effect_deps_not_strings`,
from the `verdicts` corpus). Its sibling `verdict_door_service_unknown_lifetime`
— the other #294 OD-1 control, and the other *shape* of door refusal — exists
in `tests/fixtures/verdicts/` and is already digest-pinned by the sweep, but has
no committed artifact, so no reduction exercises it.

The plan is therefore an **insertion, not a re-authoring**: add one entry to
`manifest.json`'s `artifacts` ledger naming the case and its corpus, and let
the two `--write` passes author the three goldens. Insertion-stable by
construction — the manifest's `artifacts` array is read by name, every golden
is a pure function of its own case, and `digests.json` already carries the
document, so **no existing record churns and exactly one case appears**. That
is the same rule `_check_insertion_stability` already gates on the digest
ledger.

With both in the corpus, the census can say the declared boundary is
*exercised* rather than *declared*.

### 2.4 The render configuration for the derived SARIF surface

One frozen, named configuration, and it is named identically on both sides so
that "the same configuration" is checkable rather than assumed:

```text
severity = "error"
  reference : ownlang.ownir.build_sarif(findings, "error")
  port      : own_bridge::render::build_sarif(&findings, "error")
```

`severity` is the only presentation parameter either builder takes; it sets
each result's `level` and nothing else. Recording the configuration *in the
artifact* is what stops a later reader from assuming a default: two engines
rendering the same findings under different severities would differ for a
reason that is not a divergence.

### 2.5 The C# samples: consumable without re-extracting? — **yes**

The question F.0 owes, because #260 forbids running the extractor twice.

**Measured against the workflow:** `ci.yml`'s `wpf-extractor` job
(`C# leak extractor (Roslyn) -> OwnIR -> core`) runs
`OwnSharp.Extractor` **once** over the sample set and writes one file,
`$RUNNER_TEMP/facts.json`. Every later step in that job re-reads that same
file; nothing re-extracts. The file is not published, so today it is
unreachable from any other job — which is a *packaging* gap, not an extraction
one.

**Answer: yes, and it is listed for F.5.** One `actions/upload-artifact` step on
the existing extractor job publishes those exact bytes; the compare gate takes
them with `needs:` + `actions/download-artifact` and hands the file to the
driver, which reads it **once, as bytes**. The extractor still runs exactly
once in the workflow, the byte sequence crosses the job boundary unchanged, and
the driver's own attestation (`input.raw` vs each engine's `consumed`) is what
proves it — the same evidence it produces for a committed fixture, with no
special case for this path.

**What that answer does not claim.** Whether the samples' OwnIR *compares
clean* is not measured here: this environment has no .NET SDK, so the extractor
cannot be run. The gate is wired to take that measurement in the one place that
can, and its result is reported rather than predicted. A divergence there would
be a finding to record, not a gate to relax.
