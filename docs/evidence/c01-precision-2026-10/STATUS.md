## Главный вывод для владельца (факты → вывод)
- Факт: у 21 из 25 подтверждённых ACTIONABLE на MAUI в том же файле есть `-=` (`diagnosis.md` §1).
- Факт: основная масса REL-ложных стоит на `DisconnectHandler`/`Disconnect`/`OnParentChangedCore`/`UntrackTarget`,
  вызов которых при уничтожении владельца в коде фреймворка не доказан; среди ACTIONABLE есть случай с `-=` именно в
  `DisconnectHandler` (H1-076).
- Вывод: Own.NET может доказательно отличать безопасное от опасного только там, где отписка стоит на доказанном
  teardown-пути того же объекта. Для большинства предупреждений MAUI это требует модели жизненного цикла платформы или
  знания приложения — следующего решения владельца, не ещё одного фильтра.

## Оговорки
- Унаследованные допущения: корень `Dispose` действительно вызывается (AX4); переприсваивание поля между `+=` и `-=`
  не отслеживается (AX6/#163). Новая оговорка того же рода: для не-`sealed` класса наследник может заново реализовать
  интерфейс — та же дыра, что у существующего ребра `M()` для `virtual`-методов (`result.md` п. 4). В области MAUI
  наследников трёх классов нет.
- Все анализы — Python reference engine; Rust равен ему на этих входах. Конфигурация — Linux loose-mode без reference
  packs (как H1); у gong-wpf-dragdrop из-за этого 0 предупреждений (все подписки OWN050).
- Оценщик и разметчики H1 — та же модель (`claude-opus-5-5`); «независимый» = другой контекст без доступа к патчу и
  гипотезе. Его список открытых файлов — с его слов; журнал вызовов не проверялся.
- Метрика A H1 не пересчитывалась (выборка изменилась).
- Не запускались: полный `cargo test`, clippy, formal/Kani, Windows-джобы CI, oracle/mine, `owen --engine` Stage-контроли.
