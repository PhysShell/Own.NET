# formal/p037-rocq — plain-Rocq proof package for the P-037 kernel

Consolidates the research results of PRs #367 (MathComp spike), #369 (plain
Rocq control: KILL MATHCOMP, KEEP Rocq) and #370 (Election reuse gate: KEEP
generic theory) into one self-contained package on Rocq 9.2, Corelib +
Stdlib only. No MathComp, Hierarchy Builder or elpi. Research/manual
toolchain only — not a production, root-workspace or CI dependency.

See [`docs/notes/p037-rocq-consolidation.md`](../../docs/notes/p037-rocq-consolidation.md)
for the consolidation decision and what this package does and does not prove.

```text
export/                     exporter: prints theories/RustTables.v from the
                             REAL formal/p037-kernel (moved from
                             formal/mathcomp-spike/export, PR #367; output
                             retargeted to plain-Rocq import lines directly,
                             no other change)
theories/Lfp.v               generic solver theory (states = plain functions, =1 equality)
theories/P037.v               the P-037 instance + certificate checker chain_lfp
theories/RustTables.v         GENERATED by export/ -- do not hand-edit
theories/Correspondence.v     the drift seam: full tables + 300 certified Rust traces
theories/Election.v           the election pre-solver (K10e) as a separate instance
                               of the same generic Lfp.v -- Lfp.v itself is unchanged
theories/Audit.v              Print Assumptions for the P037 chain (all closed)
theories/ElectionAudit.v      Print Assumptions for the Election chain (all closed)
mutants/run_mutants.py        11 negative controls (7 Rocq-side, 4 Rust-kernel-side)
mutants/run_election_mutants.py  4 Election negative controls
loc.py                        LOC counter (model vs proof, and diff against a reference tree)
election_loc_gate.py          hard LOC gate for the Election instance vs the #369 base
check.sh                      regenerate + check everything; FAILS on a stale
                               committed RustTables.v rather than overwriting it
```

Toolchain:

```text
opam switch create p037-rocq ocaml-base-compiler.4.14.1
eval $(opam env --switch=p037-rocq)
opam repo add rocq-released https://rocq-prover.org/opam/released
opam install rocq-core.9.2.0 rocq-stdlib.9.2.0
./check.sh
python3 mutants/run_mutants.py
python3 mutants/run_election_mutants.py
python3 election_loc_gate.py
```

Explicitly NOT claimed by this package: a Rust<->Rocq refinement seam for
Election (only the transfer/cells solver has one, via `Correspondence.v`),
and G-T2b (a Phase-B empirical claim about the legacy analyzer, never a Rocq
theorem). Issue #368 (`solve_with` under an unfair schedule can return a
non-fixpoint) is preserved here as a recorded negative result
(`unfair_schedule_returns_bot` / `k10e_unfair_returns_bot`), not fixed — see
`P037_REOPEN_SOLVER_REQUIREMENT` in the research note for the future
constraint this implies if P-037 ever reopens.
